Local full-stack test environment used for the July 2026 senior-PM product review.
Every tester agent (and any human re-running these flows) uses this setup.

| Piece | Where |
|---|---|
| SPA + same-origin `/api` proxy | `http://<host>:24624` (scratchpad `proxy.mjs`, forwards `X-Forwarded-Host`) |

## Playwright

- Node project with playwright: `<scratchpad>/pw` (run scripts from there)
- Chromium executable: `/opt/pw-browsers/chromium-1194/chrome-linux/chrome`
- Record video: `browser.newContext({ recordVideo: { dir, size: {width:1280,height:720} }, viewport:{width:1280,height:720} })`
  (mobile flows: viewport 375×812). Save screenshots as PNG, numbered `NN-description.png`.
- Capture `page.on("console")` (errors), `page.on("pageerror")`, `page.on("requestfailed")`,
  and non-2xx/3xx responses — report them.
- curl inside the sandbox needs `--noproxy '*'` for `*.ovation.test` hosts.

## Ground truth for stats comparison

Query the DB directly, e.g.:
`psql 'postgresql://ovation:ovation@localhost:5432/ovation' -c "SELECT ..."`
Central tables: `central.clubs/players/matches/match_batting/match_bowling/match_rosters/fall_of_wickets/fielding/ladder/premiers/club_name_history`.
A club's matches: `home_club_id = :id OR away_club_id = :id`. Batting/bowling lines carry the
side's `club_id`. Leaderboard semantics (innings excludes "did not bat"; not-outs from
dismissal_type/dismissal text) mirror `lib/db/src/central-queries.ts`.

## Output conventions

Each tester writes into `docs/product-review/evidence/<area>/`:
- screenshots `NN-*.png`, videos `*.webm` (rename from Playwright's hash names)
- `findings.md` — structured: What was tested · What works well · Issues (severity,
  reproduction, evidence file) · UI-vs-DB comparison table where applicable
- the Playwright script(s) used, copied to `docs/product-review/evidence/scripts/`
